# 한국어 Transformer V2 대규모 사전 학습

기존 decoder-only Transformer의 구조와 가중치 이름을 유지합니다. V2 Attention은 PyTorch SDPA로 실행하고 V1 명령과 수동 Attention 구현은 보존합니다.

## 설치와 추천 설정

Windows PowerShell, Python 3.13.5와 CUDA 지원 PyTorch 환경:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

| 항목 | 새 학습 CLI 기본값 | 옵션 |
| --- | --- | --- |
| Embedding / Layers / Heads | 256 / 6 / 8 | --embedding-dim / --num-layers / --num-heads |
| Context / Vocabulary 목표 | 512 / 8,000 | --context-length / --vocab-size |
| Batch / Gradient Accumulation | 4 / 8 | --batch-size / --gradient-accumulation-steps |
| Learning Rate / Weight Decay | 0.0003 / 0.1 | --learning-rate / --weight-decay |
| Precision / Gradient Clip | auto / 1.0 | --precision / --grad-clip |
| Warmup | 100 Step | --warmup-steps |
| Validation / Seed | 0.1 / 1337 | --validation-fraction / --seed |

AdamW와 Warmup/Cosine Scheduler를 사용합니다. 기본 설정은 Optimizer 1 Step당 16,384개 학습 토큰입니다. 메모리가 부족하면 새 학습에서 배치를 2로, 누적을 16으로 조정할 수 있습니다.

## 데이터 처리

로컬 UTF-8 파일은 한 줄을 한 문서로 읽습니다. Hugging Face는 `streaming=True`로 읽고 NFC·공백 정규화, 빈 문서 제거, SQLite의 SHA-256 키로 정확히 같은 정규화 문서를 제거합니다. 문서 해시와 Seed로 Train/Validation을 분리하므로 같은 문서가 양쪽에 들어가지 않습니다. 근사 중복 제거는 하지 않습니다.

선택한 입력을 디스크에서 전처리한 후 CPU 메모리 매핑으로 토큰을 읽고, 학습·검증 미니배치만 GPU로 전송합니다. 전체 코퍼스를 RAM/GPU에 적재하지 않으며 첫 Optimizer Step 전에 입력 준비를 완료합니다. 디스크에는 문서 DB와 토큰당 8바이트의 토큰 파일이 필요합니다. OS 파일 캐시의 RAM 사용량은 운영체제가 관리합니다.

기본 입력 제한은 10,000문서입니다. `--max-documents N` 또는 전체 입력을 위한 `--all-documents`를 지정하세요. 준비 결과는 `dataset_cache/v2/<고유ID>/`에 저장합니다. `--cache-dir`로 위치를 변경할 수 있습니다. 캐시에는 원문 데이터가 있으므로 Git에 추가하지 않습니다.

## 소규모 GPU 확인

두 분할 모두 Context보다 긴 토큰이 나오는 문서 파일을 사용합니다.

```powershell
python -m korean_transformer_v2 train --data C:\data\korean.txt --max-documents 200 --output checkpoints\v2-check.pt --device cuda --max-steps 2 --warmup-steps 1 --eval-interval 1 --eval-batches 1 --checkpoint-interval 1
```

## 실제 학습 명령

다음은 사용자가 직접 실행할 대규모 학습 예시입니다. 한국어 위키백과는 [`wikimedia/wikipedia`, `20231101.ko`](https://huggingface.co/datasets/wikimedia/wikipedia), KorMix는 [`AdaMLLab/KorMix`](https://huggingface.co/datasets/AdaMLLab/KorMix)의 `train` 분할, `text` 컬럼을 사용합니다.

```powershell
# 한국어 위키백과 전체
python -m korean_transformer_v2 train --dataset korean-wikipedia --all-documents --output checkpoints\wiki-v2.pt --device cuda --max-steps 100000 --warmup-steps 1000 --precision bf16 --export-tokenizer checkpoints\wiki-v2.tokenizer.json

# KorMix 전체: 별도 모델과 Tokenizer
python -m korean_transformer_v2 train --dataset kormix --all-documents --output checkpoints\kormix-v2.pt --device cuda --max-steps 100000 --warmup-steps 1000 --precision bf16 --vocab-size 16000 --export-tokenizer checkpoints\kormix-v2.tokenizer.json
```

임의 Dataset Repository도 `--dataset 조직/저장소 --dataset-config 설정 --split train --text-column text`로 지원합니다. 재현 가능한 준비에는 `--revision`으로 데이터셋의 고정 Commit SHA를 지정하세요. 인증은 Hugging Face 로컬 로그인 또는 `HF_TOKEN` 환경변수를 사용하며 토큰을 체크포인트나 Git에 저장하지 않습니다.

## BPE와 재사용

새 CLI 학습은 Rust 기반 Hugging Face `tokenizers` BPE를 사용합니다. [iterator 학습 API](https://huggingface.co/docs/tokenizers/python/latest/tutorials/python/training_from_memory.html)와 ByteLevel 알파벳으로 미학습 Unicode도 처리합니다. Vocabulary 목표 8,000~16,000을 지원하며 작은 코퍼스에서는 실제 Vocabulary가 목표보다 작을 수 있습니다.

Tokenizer 학습은 Train 분할의 처음 최대 20,000문서, 20,000,000문자만 사용합니다. `--tokenizer-max-documents`, `--tokenizer-max-characters`로 메모리와 학습 시간을 조절하세요. 대표성이 있는 입력 순서를 권장합니다. 이 제한은 모델 학습 데이터에는 적용하지 않습니다.

`--export-tokenizer checkpoints\name.tokenizer.json`으로 저장하고 새 학습에 `--tokenizer-file checkpoints\name.tokenizer.json`을 지정하면 재학습하지 않습니다. 기존 export 파일은 덮어쓰지 않습니다. `--tokenizer-backend python`은 기존 Python BPE입니다. Python API는 이전처럼 Python 백엔드가 기본이므로 대규모 작업에 `tokenizer_backend="fast"`를 지정합니다.

기존 `korean_byte_bpe_v1` 체크포인트는 기존 Tokenizer와 ID를 그대로 복원합니다. 새 BPE는 ID 체계가 다르므로 기존 가중치에 교체하지 않습니다. 재개 중 Tokenizer 파일이 체크포인트와 다르면 거부합니다.

## 재개와 목표 Step 확장

정상 종료와 `--checkpoint-interval`마다 모델, Optimizer, Scheduler, Scaler, Tokenizer, Config, Step, Python/PyTorch/CUDA RNG, 데이터 지문, 누적 토큰 수를 원자적으로 저장합니다. 갑작스러운 중단은 마지막 체크포인트부터 재실행합니다. `--stop-after N`은 정상 저장 후 종료하는 절대 Step입니다.

학습 완료 출력의 `prepared_cache=...` 경로를 기록하세요. 해당 폴더의 `prepared.json`과 두 `.bin` 파일이 있으면 원본·네트워크 없이 재개합니다. `<고유ID>`를 실제 출력 경로로 바꿉니다.

```powershell
# 저장된 목표 Step까지 재개
python -m korean_transformer_v2 train --prepared-cache dataset_cache\v2\<고유ID> --resume checkpoints\wiki-v2.pt --output checkpoints\wiki-v2.pt --device cuda

# 목표 전체 Step을 150,000으로 확장
python -m korean_transformer_v2 train --prepared-cache dataset_cache\v2\<고유ID> --resume checkpoints\wiki-v2.pt --output checkpoints\wiki-v2.pt --device cuda --max-steps 150000
```

`--max-steps`는 추가 Step 수가 아닌 목표 전체 Step입니다. 생략하면 기존 목표를 유지하며 감소는 거부합니다. 확장 시 저장된 Optimizer Step 위치에서 새 목표 기준 Cosine Scheduler를 계산합니다. 이미 낮아진 LR이 확장 후 상승할 수 있습니다. 그 외 모델·학습 설정은 체크포인트 값을 사용합니다.

원본에서 다시 준비하려면 같은 입력 범위·Revision·순서로 `--data` 또는 `--dataset`을 지정합니다. 기존 V2 데이터 지문 형식도 유지합니다. 지문 또는 Tokenizer가 다르면 재개를 거부합니다. 캐시를 직접 수정하지 마세요. 캐시 로더는 설정과 파일 길이를 검사하며 파일 내용 전체의 무결성을 검사하지는 않습니다.

기존 출력은 해당 파일을 `--resume`으로 지정한 경우에만 갱신합니다. 갱신 전 파일은 `<이름>_history/`에 하드 링크로 보존합니다. 하드 링크 미지원 파일 시스템에서는 기존 파일을 보존한 채 저장이 실패합니다. 기록과 캐시는 계속 쌓이므로 디스크 공간과 불필요한 파일은 사용자가 관리합니다. V1과 다른 V2 파일은 변경하지 않습니다.

## 지표와 생성

`<출력명>.metrics.jsonl`에 성공한 Optimizer Step마다 Training Loss, Tokens/sec, LR, 누적 토큰, Precision, GPU 할당·예약·최대 할당 메모리를 추가합니다. Validation Loss는 `--eval-interval` 및 최종 목표 Step에서 `--eval-batches`만큼 기록하고 나머지 Step에는 null입니다. `--log-path`로 경로를 바꿉니다. Tokens/sec는 샘플링·전송·역전파·Optimizer를 포함하고 검증·저장·데이터 준비 시간은 제외합니다.

`auto`는 CUDA BF16 지원 시 BF16, 아니면 Scaler를 사용하는 FP16, CPU에서는 FP32입니다. `--precision fp16`도 지원하며 검증에도 같은 Autocast를 사용합니다. SDPA는 가중치 형식을 바꾸지 않지만 이전 수동 Attention과 부동소수점 결과가 완전히 같지는 않을 수 있습니다.

```powershell
python -m korean_transformer_v2 generate --checkpoint checkpoints\wiki-v2.pt --prompt "대한민국의 역사" --device cuda --max-new-tokens 100 --temperature 0.8 --top-k 40
```
